## Причина Малого Масштаба

`adjustTableScale()` в `public/poker.js` использовал меньший из коэффициентов `gr-room.clientWidth / 1750` и `gr-room.clientHeight / 1150`, с пределом 1.3. Высота `gr-room` уже учитывает верхнюю панель: обычно 80 px на desktop и 58 px в портрете.

Сам стол имеет размер 1540×840 CSS px. Браузерные замеры полного игрового расположения с картами, плашками, комбинацией и действиями дали около 950 px по высоте у 6-max и 958 px у 9-max. Прежний запас 1150 px был заметно больше необходимого.

`scale ≈ 0.44` воспроизведён при CSS viewport около 1100×586: после верхней панели остаётся 506 px, `506 / 1150 = 0.44`. В настоящем CSS viewport 1920×1080 исходный коэффициент около 0.87, не 0.44. Физическое разрешение монитора не равно внутреннему CSS viewport: на него влияют масштаб ОС, zoom, размер и панели окна браузера. Точный viewport владельца по одному физическому разрешению не определялся.

## Новый Расчёт

Для непортретной раскладки добавлена чистая функция `_desktopTableScale(width, height)`:

```js
previous = min(width / 1750, height / 1150, 1.3)
fit = min(max(0, width - 12) / 1750, max(0, height - 12) / 960)
scale = min(fit, max(1, previous))
```

Запас по высоте уменьшен до проверенной игровой области 960 px. Дополнительно оставлены 12 px свободного места суммарно по каждой оси. На средних окнах допустим размер до естественного масштаба 1.0; на больших сохранён прежний коэффициент, если он уже больше 1.0. Поэтому 2K не увеличивается до максимального заполнения экрана без необходимости. Общий предел 1.3 сохранён.

Стол по-прежнему центрируется существующим flex-контейнером и масштабируется единым `transform`: координаты мест, размеры аватаров, карты, ставки и действия не переставлялись. Пересчёт использует существующие обработчики resize/visualViewport. Портретная ветка, размер мобильного шаблона, его 4% inset и расположение панели действий не менялись.

### Игровые Надписи

Причина: desktop-панель находилась внутри `.big-table` и наследовала общий transform. В компактном окне 1100×586 scale около 0.515 превращал текст кнопки 14 px в 7.2 экранных CSS px, а высоту 54 px — в 27.8 px.

Для непортретного стола с scale < 0.99 добавлен класс `desktop-readable`. Игровая типографика получает коэффициент `1 + min(0.18, (1-scale)*0.5)`: на проверенных ноутбуках это примерно +8–18%, без увеличения всего текста подряд.

| Элемент | Было, До Transform | Стало На Ноутбуках, До Transform |
| --- | ---: | ---: |
| Размер банка | 15 px | до 17.7 px |
| Стек | 16 px | до 18.88 px, с ограничением по длине числа |
| Ставка рядом с фишками | 14 px | до 16.52 px, с ограничением по длине числа |
| Числа блайндов / ante | 14 px | до 16.52 px |
| Название комбинации | 16 px | до 18.88 px |
| Бейдж действия | 16 px | до 18.88 px |
| Полоса таймера игрока | 4 px | 5 px |

Текст типа стола, часы и HUD над столом не увеличивались без необходимости: HUD уже находится вне масштабируемого контейнера. У длинных стеков и ставок размер шрифта ограничен длиной форматированной строки: числа не сокращаются и не обрезаются. Проверены стек и ставки `$1234567890.12`, банк `$9876543210.12`, длинная сумма Call и полный текст комбинации «Фулл-хаус A на K».

Если увеличенная плашка блайндов встречается с верхними фишками, измеряется реальный конфликт. На 9-max при необходимости используются две строки; padding становится компактнее. Для центральной верхней ставки 6-max плашка занимает свободный промежуток между ставкой и board с проверкой границы карт. Ставки, карты, места и центр стола ради этого не сдвигаются.

### Панель Действий

Используется прежний `#actionControls`, внутри того же стола. `_desktopActionFit()` компенсирует table scale только для панели. Целевой итоговый scale панели — 1; он ограничен реальной шириной справа, нижней границей viewport и видимыми частями нижнего правого соседа. Левый край также учитывает свои карты, плашку и длинную комбинацию. Небольшая вертикальная поправка рассчитывается по этим границам, а не по модели ноутбука или случайной экранной координате.

Ноутбучные размеры панели: основные кнопки 48 px и текст 17 px; суммы на кнопках 16 px; преддействия 44 px / 14 px. У быстрых ставок сохранён текст 11 px, устранён перенос `2× Pot`. Ползунок получил 18 px области взаимодействия и thumb 16 px вместо 11 px. Анимация цвета/hover сохранена, но размеры компенсированной панели не анимируются, чтобы измерения не зависели от промежуточного кадра.

Сумма прежде была только `<div>`, не полем ввода. В той же области на ноутбуках показан редактируемый `betAmtInput` со шрифтом 14 px. В мобильном портрете и при исходном крупном scale остаётся прежнее отображение. Enter/blur применяют сумму, Escape отменяет черновик. Десятичная точка и запятая, `$` и BB поддерживаются; неверный ввод отклоняется. Значение переводится в существующий slider и ограничивается **его действующими min/max**, не новой формулой ставок. Обновление той же очереди хода не стирает ввод; новый ход сбрасывает старый черновик.
