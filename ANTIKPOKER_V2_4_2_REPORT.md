## Причина Малого Масштаба

`adjustTableScale()` в `public/poker.js` использовал меньший из коэффициентов `gr-room.clientWidth / 1750` и `gr-room.clientHeight / 1150`, с пределом 1.3. Высота `gr-room` уже учитывает верхнюю панель: обычно 80 px на desktop и 58 px в портрете.

Сам стол имеет размер 1540×840 CSS px. Браузерные замеры полного игрового расположения с картами, плашками, комбинацией и действиями дали около 950 px по высоте у 6-max и 958 px у 9-max. Прежний запас 1150 px был заметно больше необходимого.

`scale ≈ 0.44` воспроизведён при CSS viewport около 1100×586: после верхней панели остаётся 506 px, `506 / 1150 = 0.44`. В настоящем CSS viewport 1920×1080 исходный коэффициент около 0.87, не 0.44. Физическое разрешение монитора не равно внутреннему CSS viewport: на него влияют масштаб ОС, zoom, размер и панели окна браузера. Точный viewport владельца по одному физическому разрешению не определялся.

## Новый Расчёт

Для непортретной раскладки добавлена чистая функция `_desktopTableScale(width, height)`:

```js
previous = min(width / 1750, height / 1150, 1.3)
fit = min(max(0, width - 12) / 1750, max(0, height - 12) / 960)
scale = min(fit, max(1, previous))
```

Запас по высоте уменьшен до проверенной игровой области 960 px. Дополнительно оставлены 12 px свободного места суммарно по каждой оси. На средних окнах допустим размер до естественного масштаба 1.0; на больших сохранён прежний коэффициент, если он уже больше 1.0. Поэтому 2K не увеличивается до максимального заполнения экрана без необходимости. Общий предел 1.3 сохранён.

Стол по-прежнему центрируется существующим flex-контейнером и масштабируется единым `transform`: координаты мест, размеры аватаров, карты, ставки и действия не переставлялись. Пересчёт использует существующие обработчики resize/visualViewport. Портретная ветка, размер мобильного шаблона, его 4% inset и расположение панели действий не менялись.

Результаты реального DOM; одинаковы для 6-max и 9-max с точностью округления:

| 1366×768 | 0.598 | 0.704 |
| 1440×900 | 0.713 | 0.816 |

| 1093×614, компактное окно | 0.464 | 0.544 |

На основных ноутбучных размерах увеличение примерно 14–18%. В области достаточной высоты коэффициент приближается к 0.55; это не фиксированное значение для всех устройств. В окне с высотой игровой области 506 px принудительные 0.55 не вместили бы игровую область около 958 px целиком, поэтому выбран безопасный 0.515.

IAB иногда округляет заданные размеры на 1 CSS px, например 1536×864 до 1536×865 и 1920×1080 до 1921×1081. В JSON сохранены фактические размеры. Приоритет отдан реальному доступному месту, не названию устройства.

Размеры приведены до общего transform. Плашка вместе с padding и border укладывается в существующее место: desktop 180 px, мобильный 6-max 122 px, 9-max 104 px. Исключение для своего 6-max предотвращает заход плашки на рамку действий на 320–390 px. Полный предел 111 px для этого места давал пересечение, поэтому он не применён вслепую.

Маркер `(you)` сохранён. У собственного 9-max фактически доступная тексту ширина выросла с 26 до 56 px; на desktop — с 80 до 104 px. На узком 6-max текст получает 58 px, а не одну узкую область рядом с маркером.

Шрифты ников не уменьшались. `Alex` помещается полностью. `Guest12345678` и длинные аккаунтные имена показывают больше символов, но при реальной нехватке ширины остаются однострочными с ellipsis. Полная исходная строка остаётся в DOM, title и существующем уведомлении по нажатию/Enter; генерация имени и серверные данные не меняются. Пересечений ников соседних мест в проверенной матрице нет.

### Zoom И Ограничения

100% проверен заданными размерами. Для 125% проверены эквивалентные CSS viewport: 1093×614, 1152×720, 1229×691, 1280×720, 1536×864 и 2048×1152. Алгоритм зависит от этих доступных CSS-размеров; на них обрезания нет. **Сам переключатель browser zoom 125% в IAB не использовался**: это проверка эквивалентной раскладки, не заявление о нативном zoom или проверке физических устройств. Нативный zoom и субъективную читаемость владелец может оценить при визуальной приёмке.
