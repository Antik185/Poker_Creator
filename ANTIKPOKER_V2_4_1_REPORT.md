# AntikPoker V2.4.1

## Статус

Реализовано и проверено локально: вкладки каталога и фоновые превью карточек.
Production, рабочая SQLite, DNS, Nginx, Cloudflare и Gcore не изменялись.
Выкладка требует отдельного разрешения. Новый коммит и push в рамках этой задачи не выполнялись.

## Каталог

- По умолчанию открыта вкладка «Активные».
- Завершённость определяется существующим серверным статусом, включая сохранённый `FINISHED`, а не датой старта.
- В активных сначала идут MTT с открытой регистрацией, затем остальные незавершённые.
- Архив отсортирован по реальному `finishedAt`, от нового к старому. Записи без достоверного времени завершения идут после датированных, по реальному времени запланированного старта в обратном порядке. Отсутствующее время завершения остаётся `null` и не показывается.
- Название, описание, статус, начало, участники, лимит и существующие действия сохранены. Длинные название и описание визуально ограничены двумя строками; полный текст остаётся в DOM и `title`.
- Завершённые карточки не показывают регистрацию, даже если клиент получил противоречивый `canRegister`. Существующая серверная проверка регистрации не менялась.
- Существующее лобби остаётся доступно по прежней ссылке. Новая система результатов не создавалась.
- Пустые состояния и ошибки сети имеют отдельные сообщения. При неудачном обновлении уже загруженные карточки остаются видимыми.

### API И Обновление

Существующий `GET /api/tournaments` обратно совместим: без параметров возвращает общий список. Добавлены `status=active`, `status=finished`, поля `finishedAt` и `previewUrl`. Неизвестный фильтр возвращает 400. Персонализированный список по-прежнему имеет `Cache-Control: no-store`.

Активная вкладка опрашивается каждые 5 секунд. Архив загружается при открытии и обновляется не чаще раза в минуту, только пока открыт. Кнопка «Обновить» и восстановление сети разрешают явный повтор. Скрытая страница не опрашивается. Неиспользуемый архив постоянно не скачивается.

При переключении кеш отображается сразу, затем обновляется. Ответ от ранее открытой вкладки не заменяет текущую. Турнир, уже полученный как завершённый, не может вернуться в активные из более старого ответа.

Вкладки используют `tablist`, `tab`, `tabpanel`, `aria-selected`, управляемый `tabindex`; доступны стрелки, Home, End, Enter и Space. Переключение не перезагружает страницу.

## Превью

Изучена текущая модель: отдельного поля миниатюры или tournament preview-art сейчас нет. Используются существующие изображения связанной комнаты:

1. `room.felt_url`, затем `config.feltPhotoUrl`.
2. Если фон отсутствует, существующий `room.logo_url` / `config.logoUrl`.
3. Иначе общий fallback из уже имеющегося `public/site/assets/images/real-table.webp`.

Новая система хранения, поля SQLite и копии оригиналов не создавались. Загрузчик стола и его оптимизация не изменены.

### Лёгкая Производная

`GET /api/tournaments/:id/preview` читает только существующий локальный файл изображения из uploads и отдаёт производный WebP. Используется уже установленный Sharp:

- до 640 × 400 px, максимум 96 КиБ на ответ;
- при необходимости снижение до 480 × 300 или 320 × 200 и уменьшение качества;
- первый кадр анимации, без анимации и исходных метаданных;
- исходник не больше 5 МиБ и 16 миллионов пикселей;
- максимум два преобразования одновременно и очередь из 16;
- ограниченный LRU-кеш в памяти: до 64 записей / 6 МиБ; совпадающие запросы объединяются;
- версия URL зависит от метаданных источника, есть ETag/304 и браузерный кеш на час;
- повреждённая картинка временно заменяется fallback с кешем на минуту, при недоступности endpoint остаётся CSS-фон.

Обрабатываются только имена локальных файлов существующего формата uploads. Нет HTTP-запросов по пользовательским URL, обработки `data:` или доступа за пределы uploads; выход через symlink отвергается. Превью обычных не-MTT комнат через этот endpoint не раскрываются.

Изображение расположено абсолютным фоновым слоем с `object-fit: cover`, а не отдельным блоком карточки. Поверх него затемняющий градиент и текст. Inline-style не требуется, CSP сохранена. Используются `loading=lazy`, `decoding=async`, пустой alt и скрытие декоративной картинки от accessibility tree. Фон есть в обеих вкладках.

На проверенных локальных изображениях размер ответа составил 1 996–39 126 байт; общий fallback — 22 386 байт. Это измерения конкретных образцов, а не обещание такого размера для всех изображений. Жёсткий предел — 98 304 байта.

## Готовность И Ограничения

Локальная реализация готова к согласованию публикации. Миграции не нужны; движок, TournamentManager, регистрация, результаты, история, upload pipeline и оригиналы не изменены. После будущей выкладки существующие завершённые MTT будут отфильтрованы из тех же записей, без переноса данных.

Остаётся обычная проверка фактического каталога и превью после отдельно разрешённого deployment. Во время текущей задачи production не опрашивался, поэтому отображение его конкретных 20 записей не объявляется проверенным на live-сайте.

После перезапуска процесса небольшой кеш превью прогреется заново по запросам. На очень большом архиве может понадобиться пагинация; сейчас она не вводилась. Внешние и нестандартные пути изображений намеренно заменяются fallback, а не скачиваются сервером.
